# 叙事骨架（维度 `D` 的推荐依据）

五种论证结构。它决定页面顺序、标题语气和每页的结构倾向。

**它不是要跟用户确认的术语。** 先按选择规则挑一个，据此生成逐页大纲，向用户
展示的是大纲，骨架名只作为一句理由带过（「按结论先行的顺序排」而不是
「我选了 pyramid 模式」）。

**它和视觉风格 `E` 正交。** 任何骨架配任何风格都成立——结论先行的材料可以是
瑞士极简，也可以是深色科技。挑其中一个时不要连带限制另一个。

---

| 骨架 | 论证结构 | 标题语气 | 选择规则 |
|---|---|---|---|
| `pyramid` 金字塔 | 结论先行，逐层给支撑证据，最后收束为行动 | 每页标题是判断句 | 适用于要对方做决定的材料（审批、选型、投资建议）。若受众需要的是完整参考而非被说服，改用 `briefing`。 |
| `briefing` 简报 | 中立、完整、可扫读，同类项等权呈现，不预设立场 | 每页标题是主题词 | 适用于状态同步、参考手册、目录、会议材料包。若材料的目的是推动一个决定，改用 `pyramid`。 |
| `narrative` 叙事 | 情境 → 冲突 → 转折 → 收束，有悬念 | 标题推进故事 | 适用于路演、案例、品牌历程、融资。若受众按分钟计时且只想要结论，改用 `pyramid`。 |
| `instructional` 教学 | 概念拆解、分步推进、平行展开 | 标题是知识点 | 适用于培训、教程、原理讲解。若内容不需要被学会而只需被知晓，改用 `briefing`。 |
| `showcase` 展示 | 视觉主导，大图或大数字，情绪节奏 | 标题短促有力 | 适用于发布会、品牌揭幕、活动宣传。**要求有高质量图像素材**；素材不足时改用 `pyramid` 或 `narrative`。 |

---

## 混合

预设不够用时填 `custom`，并写一段 `骨架说明` 讲清由哪几个各负责什么。例如：

```
骨架: custom（pyramid + briefing）
骨架说明: 以结论先行为主轴，每页标题写判断；同时保留简报的完整可扫读纪律——
          同类方案等权呈现、不夸大任一项、每张数据页带来源与口径行。
```

宁可写 `custom` 加两句说明，也不要硬套一个不合适的预设。

## 骨架对页数的影响

`pyramid` 和 `briefing` 页数由内容决定，可以很短（四到六页）。
`narrative` 需要铺垫，低于六页容易失去张力。
`instructional` 按知识点数量走，通常最长。
`showcase` 页数多但每页很轻。

推荐页数时把这条纳入考虑，但**用户给的上限永远是硬上限**——放不下就压缩内容
或合并页，不要突破上限。
