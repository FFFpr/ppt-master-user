# 页型库（维度 `H`）

20 种 PowerPoint 原生版式。方案里写 `页型: <id>`，下游按 id 取版式，你只需要
填槽位内容和约束。

**每个条目是选择规则，不是描述。** 按「适用于」匹配内容形态；命中「改用」条件
就换。不要按名字顺眼程度选，也不要按页码位置默认（第一页不必然是 `title_slide`）。

**槽位是软约束。** 槽位列表说明这个版式原生准备了哪些位置。内容块数量与槽位
不完全吻合是允许的，多出的块在方案里写清归属；差距大到需要空一半槽位时，
说明选错了版式。

---

## 1. 封面与分章

| id | 名称 | 槽位 | 选择规则 |
|---|---|---|---|
| `title_slide` | 封面 | 标题 · 副标题 | 适用于开篇建立主题与前提。若封面需要同时摆出一个决定性数字或结论，改用 `hero_statement`。 |
| `section_header` | 章节页 | 章节标题 · 章节说明 | 适用于八页以上、需要分段喘息的长文。若全文六页以内，删掉分章页，直接进内容。 |
| `title_only` | 仅标题 | 页标题 | 适用于标题本身即全部信息，下方留给现场演示或口头展开。若阅读模式是「自足」，改用 `title_content`。 |
| `blank` | 空白 | 无 | 适用于整页由一张图或一个自定义构图承担。**慎用**：它把全部布局责任推给下游，只在其余 19 种都明显不合时选。 |

## 2. 通用内容

| id | 名称 | 槽位 | 选择规则 |
|---|---|---|---|
| `title_content` | 标题＋内容 | 页标题 · 内容区 | 适用于单一主题的连续陈述，内容形态不定。**这是默认兜底项**——想不清楚用哪个时用它，不要为了显得丰富而硬选花哨版式。 |
| `content_caption` | 内容＋注释栏 | 页标题 · 内容区 · 注释 | 适用于主体内容需要一条持续的旁注、口径说明或免责声明。若注释只有一行且属于来源，改用 `title_content` 把来源放页脚。 |
| `hero_statement` | 焦点主张 | 核心主张 · 限定语 | 适用于整页只讲一句话，且这句话需要被记住（决议、承诺、单一结论）。若同页还要摆证据，改用 `data_story`。 |
| `editorial_split` | 编辑式分栏 | 页标题 · 正文 | 适用于文字为主、需要一侧配图或留白形成呼吸感的叙述页。若两侧都是文字且地位平等，改用 `two_content`。 |

## 3. 并列与对比

| id | 名称 | 槽位 | 选择规则 |
|---|---|---|---|
| `two_content` | 左右并列 | 页标题 · 左内容 · 右内容 | 适用于两组**平级但不对立**的内容（两个方向、两类事项）。若两组是同一批准则下的正面交锋，改用 `comparison`。 |
| `comparison` | 对比 | 页标题 · 左标题 · 左内容 · 右标题 · 右内容 | 适用于两方在同一批准则上逐项比对，且需要各自的小标题。若准则超过四项或涉及三方以上，改用 `table_summary`。 |
| `three_card` | 三卡片 | 页标题 · 卡片 ×3 | 适用于恰好三个平级要点，且每点篇幅相近。**若要点数量不是三、或篇幅悬殊，改用 `title_content` 列表**——硬凑三个是这个版式最常见的误用。 |
| `process_timeline` | 流程时间轴 | 页标题 · 步骤 ×4 · 结论栏 | 适用于四步以内的有序流程或时间推进，顺序本身是信息。若顺序无意义，改用 `three_card` 或 `two_content`。 |

## 4. 数据与证据

| id | 名称 | 槽位 | 选择规则 |
|---|---|---|---|
| `kpi_dashboard` | 指标看板 | 页标题 · 指标 ×4 · 证据区 | 适用于四个并列的关键数字打头、下方一块证据支撑。若数字不足三个，改用 `hero_statement` 突出单个；超过六个，改用 `table_summary`。 |
| `chart_insight` | 图表＋解读 | 页标题 · 关键结论 · 来源 | 适用于一张图表承担全页论证，配一句解读和来源行。**图表类型不在这里选**，在内容块里写明图表形态与数据。若同页要两张以上图表，改用 `data_story`。 |
| `table_summary` | 表格＋小结 | 页标题 · 关键结论 · 来源 | 适用于多行多列的结构化对照，行列数超过对比版式的承载力。若只有两列且需要各自标题，改用 `comparison`。 |
| `data_story` | 数据叙事 | 页标题 · 证据区 · 关键信息 · 来源 | 适用于证据区形态复杂（图表加表格、多图并置）且需要一条解读轨与来源行。**信息密度最高的版式**，页面会很满，稀疏内容不要用。 |

## 5. 图像

| id | 名称 | 槽位 | 选择规则 |
|---|---|---|---|
| `title_picture` | 标题＋大图 | 页标题 | 适用于一张图本身即论据（现场照、产品图、示意图）。若图需要配解释文字，改用 `picture_caption`。 |
| `picture_caption` | 图＋说明栏 | 页标题 · 说明 | 适用于图配一段解释或出处。若解释比图更重要，改用 `editorial_split`。 |
| `two_picture_caption` | 双图＋各自说明 | 页标题 · 左说明 · 右说明 | 适用于两张图对照（前后、方案 A/B），各配独立说明。若两图不构成对照关系，拆成两页。 |
| `screenshot_focus` | 截图聚焦 | 页标题 · 标注 · 来源 | 适用于软件界面、报表截图，需要在图上标注重点并注明出处。普通照片不要用这个，改用 `picture_caption`。 |

## 常见误用

**把 `three_card` 当万能并列。** 它只服务恰好三项且篇幅相近的内容。四项用
`process_timeline`（有序）或 `kpi_dashboard`（数字），不定项用 `title_content`。

**给稀疏内容选 `data_story`。** 这个版式的密度预期很高，内容不够会显得空旷。

**每页都换版式求变化。** 同类内容用同一版式，跨页一致性本身就是设计。相邻两页
若内容形态相同，用同一个 id 是正确的，不是偷懒。

**用 `blank` 逃避决策。** 想不清楚时的正确兜底是 `title_content`，不是 `blank`。
