# `plan.md` 格式契约

唯一产出物的结构定义。读者是 PowerPoint（或其他具备推理能力的下游），不是人类
施工队——所以给约束和语义，不给坐标和逐字文案。

## 三条格式原则

**锚点区用扁平键值。** 它每页都要被回读一次，`- 键: 值` 一眼定位，散文和嵌套
列表都不行。

**约束强度靠标注，默认最松。** 三级：

| 标注 | 含义 | 用在哪 |
|---|---|---|
| `[锁定]` | 必须逐字/逐值照办 | 法务声明、品牌口号、引述原文、用户点名不许改的数字 |
| `[语义]` | 事实、关系、禁止项必须保住，表达方式可变 | 有数据的结论块、对比关系、口径说明 |
| 不标 | 参考，下游可自由发挥 | 其余全部 |

**默认不标。** 只在真的不能变的地方标 `[锁定]`，在"改措辞可以、改事实不行"
的地方标 `[语义]`。满篇 `[锁定]` 等于没有分级，下游会当噪音忽略。

**颜色和字号只写角色名。** 页面描述里出现 `#0B2545` 或 `36px` 都是错的，
写 `主色`、`页标题`。映射只在锚点区出现一次，改色改字号只需改一处。

## 字段说明

### 页级头部

```
- 页型: `<id>`
- 核心: <这一页要让读者接受的那件事>
- 关系: <块间逻辑关系，只用六个词，见下>
- 焦点: <块名>
- 次级: <块名, 块名>
- 衬底: <块名, 块名>
```

顺序是从内容到表现：页型给骨架，核心说这页讲什么，关系说块之间什么逻辑，
焦点三行说视觉权重。

**一页只能有一个焦点。** 焦点、次级、衬底三档就够了，不要再细分——下游需要的
是主次判断，不是精确权重。

**`关系` 行只用这六个词**：`order` 有先后 · `link` 互相限定 · `parent` 派生从属 ·
`membership` 同属一组 · `contrast` 对立 · `overlap` 某维度一致。多组关系用分号
隔开，括号里补一句为什么。没有块间关系就写 `关系: 无`。

**禁止在这一行写形状。** 「用大括号括起来」「加个箭头」「放在左边」都不行——
关系是语义，形状是下游按版式和留白条件做的判断。同一个 `link`，它可以用箭头、
连接线、缩进层级或位置邻近来表达，方案不该替它选。

这一行是下游的**构图开关**：全页只有 `membership` 时用页型默认版式即可；出现
`link`、`parent` 或 `order` 时，下游知道要额外做点什么来表达那个关系，而不只是
把块并排摆开。权重（焦点三行）告诉它谁大谁小，关系告诉它谁连着谁，缺了后者
页面会变成一堆互不相干的方盒子。

### 内容块

```
**<块名>**（角色: <排版角色> / <颜色角色>）[约束标注]
<内容要点，块级粒度>
<约束补充：什么必须保住，什么不能做>
来源: <材料标记>
```

**块名要能被引用**——焦点/次级/衬底那三行引用的就是它。

**角色栏**：`/` 左边是排版角色、右边是颜色角色；`+` 叠加同一侧的多个角色
（`数据 + 焦点数字 / 强调文字`）。颜色角色可整个省略，省略时下游按默认取。

**约束补充只在 `[语义]` 块写**，说清哪些事实和关系不能丢。上例里"三者缺一则
对比不成立"就是这种约束——它比逐字锁定宽松，但守住了论证的完整性。

**`来源` 行**：含数字、名称、日期、引述的实质内容块要有。没有来源就写
`来源: [待补：<缺什么>]`。页标题和导语是对同页内容的概括，不必重复标。

### 表格与图表块

不指定具体图表类型的渲染细节，只写数据形态和要表达的关系：

```
**四档对照表**（角色: 数据）[语义]
行 = 四档规格（8核32G / 16核64G / 32核128G / OSS 50TB）
列 = 实例规格 / 数量 / 单台月价 / 小计年费 / 定位
主力档（8核32G）需要视觉区分，用强调色标记行首。
合计行：117,985.53 元/年，须注明不含项。
来源: M1, M2
```

```
**存储成本条形图**（角色: 数据）[语义]
横向条形，两项：阿里云 OSS 55,296 · 腾讯云 COS 72,499
阿里云用强调色，腾讯云用次强调，差额 17,203 元需要单独标出。
数值轴从 0 起，不得截断。
来源: M1
```

**"数值轴从 0 起，不得截断"这类约束要写**——它是会实质影响读者判断的，属于
`[语义]` 的保护范围。

### 页级例外

某页需要偏离锚点时，在页级头部加一行并注明理由：

```
- 例外: 焦点数字用 64（超出阶梯的 48），理由：封面唯一大数，需要跨会议室可读；
  用户 2026-09-07 已批准
```

**例外必须有批准记录。** 没有用户批准的偏离不写进方案。

## 收尾

方案末尾附两块：

```markdown
## 四、待补清单

| 位置 | 缺什么 | 建议来源 |
|---|---|---|
| P03 合计行 | 云盘与带宽单价 | 阿里云控制台询价 |

## 五、给下游的说明

- 本方案未指定任何坐标与元素尺寸，版面细节由 PowerPoint 按页型与主次关系决定。
- 未标注的字段均为参考，可按实际渲染效果调整。
- `[锁定]` 的措辞与数值不得改动；`[语义]` 的块可改表达，但列出的事实、关系与
  禁止项必须保留。
- 每页的「关系」行说明块之间的逻辑，**用什么形状表达由你决定**。出现 `link`、
  `parent` 或 `order` 时，请用某种视觉手段让读者看出这层关系——连接、指向、
  包含、层级缩进、顺序编号都可以——而不要只把这些块并排摆开。只有
  `membership` 或 `无` 时，页型的默认排布即可。
- 色板与字号阶梯是全文一致性的依据，逐页不得自行引入新值（页级例外已在该页
  标注）。
```

**「给下游的说明」这一节不要省。** 它是把三级约束标注和「关系」行解释给
PowerPoint 听的地方——不解释，标注就只是一堆方括号，关系词也只是六个陌生
英文单词。
