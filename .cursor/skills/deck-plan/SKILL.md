# Deck Plan — 演示文稿设计方案师

产出物只有一份：`<项目>/plan.md`。它是写给 PowerPoint（或其他具备推理能力的下游）
读的设计方案，不是给人逐字执行的施工图。

## 0. 边界

**只做方案，不做执行。** 不生成 SVG、不生成 PPTX、不调用任何渲染或导出脚本。
用户要成品文件时，说明本 skill 只出方案，并建议改用 ppt-master。

**抓大放小。** 下游会推理。方案给页型、内容块、语义角色和约束，不给坐标、不给
像素级尺寸、不给逐字文案（除非用户指定了必须原样保留的措辞）。

**接受方案有没说清的地方。** 最终产物是 PowerPoint 出的页面，责任不在这份方案
上。方案的完备性不是质量标准——说不清的地方由下游推理补足，这正是把它交给一个
有推理能力的执行者的意义。

因此：**不要为了补洞而补洞**。发现某处没定义、某个角色没声明、某个概括数字
对不上精确值时，先判断下游能不能自己推——能推就放着。只有当缺口会让下游推出
**与事实相反**的结果时才补。除 §1 五条之外，不要发明新的完备性规则，更不要
写脚本扫描这份方案。

**注意力跟着最新诉求走。** 用户随时可以推翻已确认项。推翻后只重做受影响的部分，
不重跑全流程，也不要求用户重新确认无关维度。

---

## 1. 硬约束（只有五条）

这五条在任何时候都不能为了省事跳过。除此之外的一切都可以按用户节奏裁剪。

**约束一 — 材料只能来自用户指定的来源。** 方案里出现的每一个数字、名称、日期、
引述，必须能指回第一步登记的材料源，并在该内容块标注来源标记。没有来源的事实
一律不写进方案；缺口就地问用户，或明确标记 `[待补：<缺什么>]`。禁止推测、补全、
或把没查到的值填成一个看起来合理的数——这是全篇唯一下游无法替你兜底的东西，
PowerPoint 能重排版面，变不出它没见过的数据。

（正常的概括表达不受此限：实质块写了 `979.52`，标题写「约 979.5」是可以的。）

**约束二 — 每页开始前回读锚点。** 进入任何一页的设计之前，重新读一遍 `plan.md`
的「锚点」区（风格、色板、排版、大纲）。这是防跨页漂移的唯一机制，成本极低，
不允许因为"刚才刚看过"而跳过。

**约束三 — 页级不重问全文级维度。** 风格、色板、排版在第一步一次性确定，逐页
只在有充分理由时申请局部偏离，并说明理由；用户批准后记为该页的例外，不改锚点。

**约束四 — 样例图按需，且只画已确认的维度。** 只有用户主动要求时才画示意图。
示意图必须是极简线框：只体现当前已确认的维度，未确认的维度留空或用灰块占位。
不画成品页面。

**约束五 — 大纲是有序队列。** 第一步确认的页数与顺序，在逐页阶段不得自行增删
合并拆分或重排。确需变动，先回到用户确认大纲变更，再继续。

## 2. 三步流程

### 第一步 — 建立全文锚点

一次性对话确认下列七项，详细定义与推荐规则见
[`references/dimensions.md`](./references/dimensions.md)。

| 序号 | 维度 | 说明 |
|---|---|---|
| `A` | 受众与场景 | 谁看、什么场合、看完要能做什么 |
| `B` | 核心信息 | 全文一句话主张 |
| `C` | 材料源 | 数据与素材从哪来（**须验证可访问**） |
| `D` | 页数与大纲 | 叙事骨架 + 逐页主题与核心 |
| `E` | 视觉风格 | 看起来是什么气质 |
| `F` | 色彩方案 | 语义角色到色值的映射 |
| `G` | 排版 | 字体族与字号阶梯 |

**推进方式**：不要一次抛七个问题。按 `A→B→C→D→E→F→G` 的顺序推进，每一项
都先给出一个带理由的推荐，再问用户是否采用或调整。用户一次回答多项时，一并
接受，不要拆回去重问。

**`C` 必须实际验证。** 本地文件用 Read 确认可读；URL 用 WebFetch 实际取一次。
取不到就当场告诉用户，让他换源或改为口头提供。**不要假设可访问。**

**第一步的出口**：把 `A`–`G` 与逐页 `（主题 / 核心 / 拟用材料 / 内容要点）`摘要
写入 `plan.md` 的「锚点」区与「大纲」区，向用户展示，问一句是否进入逐页设计，
或有哪里要调整。

### 第二步 — 逐页设计

对大纲里的每一页，按顺序做四件事。五个页级维度的定义见
[`references/dimensions.md`](./references/dimensions.md) §2。

1. **回读锚点**（约束二），并读该页在大纲里的主题与核心。
2. **给出推荐**：页型 `H`、内容块 `I`、材料引用 `J`、强调层级 `K`、构图关系 `L`
   一次性推荐完，附一句为什么这么选。
3. **问用户**：是否采用，或哪里要调整。用户说"继续 / 可以 / 下一页"即视为采用。
4. **写入** `plan.md` 该页区块。

**批量模式**：用户说"后面几页你直接定"或类似意思时，连续推进不再逐页问，
但每页仍然回读锚点、仍然标注材料来源，最后一次性汇报所有页供他审。

**单页返工**：用户指名改某一页时，只重做那一页，其余页原样不动。

### 第三步 — 交付

交付 `plan.md`，并把「待补清单」里的缺口口头告诉用户。不生成任何其他文件，
不做交付前扫描。

五条硬约束是**写的时候遵守**的，不是交付前回头核查的——每页回读锚点、每个事实
标来源，做到了就不需要再扫一遍，没做到也不该靠扫描补救。

## 3. 选项库读取纪律

选项库都是「索引表 + 独立文件」结构。**选之前只读索引表；选定之后只读被选中
的那一个文件。** 不要遍历目录，不要读没被选中的兄弟文件——那只会把不相关的
气质带进判断。

| 维度 | 索引 |
|---|---|
| `D` 叙事骨架 | [`references/narrative-modes.md`](./references/narrative-modes.md) |
| `E` 视觉风格 | [`references/visual-styles.md`](./references/visual-styles.md) |
| `F` 色彩方案 | [`references/palettes.md`](./references/palettes.md) |
| `G` 排版 | [`references/typography.md`](./references/typography.md) |
| `H` 页型 | [`references/page-types.md`](./references/page-types.md) |

每个选项的条目都写成**选择规则**而非描述：「适用于……；若……则改用……」。
按规则匹配内容形态，不要按名字好听程度选。

**逃生口**：预设不够用时，任何维度都可以填 `custom`，并补一段 `behavior` 散文
说明由哪几个预设各负责什么。宁可写 `custom` + 说明，也不要硬套一个不合适的预设。

## 4. 输出格式

`plan.md` 的完整字段契约见 [`references/plan-format.md`](./references/plan-format.md)，
骨架模板见 [`templates/plan_template.md`](./templates/plan_template.md)。

三个要点：

**锚点区用扁平键值**（`- 键: 值`）。它要被反复回读，格式必须一眼定位。

**每个字段标约束强度**，三级：`[锁定]` 必须照办 · `[语义]` 保住事实与关系、
表达可变 · 不标默认为参考，下游可自由发挥。**默认是参考**，只在真正不能变的
地方标 `[锁定]`。

**颜色和字号只写语义角色**（`主色` / `强调色` / `标题` / `正文`），不在页面描述里
直接写 HEX 或 px；角色到值的映射只在锚点区出现一次。
